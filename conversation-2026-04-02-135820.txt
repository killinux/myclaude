  ---
  QueryEngine.ts 全面解析

  文件结构概览

  QueryEngineConfig (type)     ← 配置对象类型定义 L130-173
  QueryEngine (class)          ← 主类 L184-1177
    constructor()              L200
    submitMessage()            L209-1156  ← 核心方法（AsyncGenerator）
    interrupt()                L1158
    getMessages()              L1162
    ...
  ask() (function)             L1186-1295 ← 对 QueryEngine 的便捷封装

  ---
  核心：submitMessage() 的执行流程

  submitMessage(prompt)
  │
  ├─① 包装 canUseTool → 追踪权限拒绝记录
  │
  ├─② 构建 System Prompt
  │     fetchSystemPromptParts() → defaultSystemPrompt + userContext
  │     + memoryMechanicsPrompt（如果有 MEMORY_PATH_OVERRIDE）
  │     + appendSystemPrompt
  │
  ├─③ 处理用户输入（斜杠命令等）
  │     processUserInput() → { messages, shouldQuery, allowedTools, model }
  │     push 到 mutableMessages
  │
  ├─④ 持久化 transcript（用户消息先写盘，防止被杀后无法 --resume）
  │
  ├─⑤ yield buildSystemInitMessage()  ← 第一个 yield，SDK 系统初始化消息
  │
  ├─⑥ 如果 !shouldQuery（斜杠命令本地执行）→ yield 本地结果 → return
  │
  └─⑦ 进入主循环：for await (message of query(...))
        │
        ├─ 'assistant'   → push + yield（含流式文本）
        ├─ 'user'        → push + yield（工具调用结果）
        ├─ 'progress'    → push + yield（工具执行进度）
        ├─ 'stream_event'→ 累计 token 用量（message_start/delta/stop）
        ├─ 'attachment'  → 处理 max_turns、structured_output 等特殊信号
        ├─ 'system'      → 处理 compact_boundary / api_error / snip
        └─ 'tool_use_summary' → yield 给 SDK
        │
        ├─ 每轮检查 maxBudgetUsd 是否超出 → 超出则 yield error_max_budget_usd
        └─ 检查 structured output 重试次数

        循环结束 → yield result (success / error_during_execution)

  ---
  关键设计点

  1. 它是一个 AsyncGenerator
  submitMessage() 用 yield* 流式输出消息，调用方通过 for await 消费：
  - 实时拿到 AI 的流式文本
  - 实时拿到工具调用进度
  - 最后收到 type: 'result' 作为终止信号

  2. mutableMessages vs 局部 messages
  mutableMessages  ← 跨多轮 turn 持久保存的消息历史（QueryEngine 生命周期内）
  messages         ← submitMessage 内的局部副本，传给 query()
  两者在循环中同步 push，但 messages 还会在 compact_boundary 时被 splice
  截断以释放内存。

  3. 两层消息处理
  - processUserInput() — 处理斜杠命令，返回 shouldQuery 决定是否调用 API
  - query() — 真正向 Anthropic API 发请求并执行工具调用（在 src/query.js）

  4. ask() 函数
  第 1186 行，是对 QueryEngine 的一次性封装：创建 engine → submitMessage → 更新
  readFileCache。外部大多数地方调用这个，而不是直接 new QueryEngine()。

  5. 终止条件（result 的几种 subtype）

  ┌─────────────────────────────────────┬────────────────────┐
  │               subtype               │        含义        │
  ├─────────────────────────────────────┼────────────────────┤
  │ success                             │ 正常完成           │
  ├─────────────────────────────────────┼────────────────────┤
  │ error_max_turns                     │ 超过最大 turn 数   │
  ├─────────────────────────────────────┼────────────────────┤
  │ error_max_budget_usd                │ 超出 USD 预算      │
  ├─────────────────────────────────────┼────────────────────┤
  │ error_max_structured_output_retries │ 结构化输出重试过多 │
  ├─────────────────────────────────────┼────────────────────┤
  │ error_during_execution              │ 其他执行错误       │
  └─────────────────────────────────────┴────────────────────┘

  ---
  下一步建议

  读完 QueryEngine.ts 后，自然要问：query() 内部是怎么工作的？

  src/query.ts   ← 实际与 Anthropic API 交互、执行工具调用的循环

  这是 QueryEngine 依赖的核心底层，建议接下来读它。
